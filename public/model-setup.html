Connect a tutor model

Keep model keys on the server. Tutair never asks for or stores provider credentials in your browser.

Choose a mode

  • Disabled keeps the learning workspace local without generation.
  • Demo exercises the workflow with an explicit synthetic banner. It is not presented as a real model.
  • OpenAI-compatible connects a provider that supports the required structured-output schema.
  • Personal ChatGPT uses official local OAuth and the Responses API when the server explicitly enables it.

Configure the server

Set environment variables where the Tutair server runs, then restart it. Do not paste these values into browser storage or a conversation.

# Synthetic workflow demo
TUTOR_PROVIDER=demo

# OpenAI-compatible provider
TUTOR_PROVIDER=openai
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_API_KEY=your-provider-key
TUTOR_MODEL=gpt-4.1-mini

# Personal local ChatGPT mode
TUTOR_PROVIDER=chatgpt
TUTOR_CHATGPT_PERSONAL=true
TUTOR_CHATGPT_CALLBACK_PORT=1455

# Optional provider embedding model
TUTOR_EMBEDDING_MODEL=text-embedding-3-small

# Or use local embeddings
TUTOR_EMBEDDING_PROVIDER=local

Loopback callback

Personal ChatGPT uses http://127.0.0.1:1455/auth/callback. Open Tutair through that same loopback port. For a container or VM listening on port 3000, forward it first: ssh -N -L 1455:127.0.0.1:3000 user@vm. Do not replace 127.0.0.1 with localhost or a public callback.

Check the connection

Return to Tutair and open Settings → Session & model. The status identifies the configured model, synthetic mode, or unavailable generation. A real-provider failure never silently falls back to synthetic output.

Privacy note

Your configured provider may receive learning context needed for a tutor turn. Review that provider’s retention policy before using sensitive learning material.
